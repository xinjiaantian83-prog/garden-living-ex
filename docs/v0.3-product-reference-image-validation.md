# Version 0.3 Product Reference Image Validation

Last updated: 2026-07-12

## Purpose

Version 0.3 validates the product image reference method for Garden Living AI
simulation.

The goal is not placement quality.

The goal is product reproduction:

- shape
- color
- material
- detail
- product match rate

## Result

Version 0.3 is accepted.

The target success condition was product match around 85 points or higher.

| Product | Final Match Score | Result |
| --- | ---: | --- |
| Pizza oven | 88-90 | Accepted |
| Gabion | ~85 | Accepted |
| Water stand | 86 | Accepted |

## Confirmed Design Direction

Do not send every gallery image to the image model.

Use the product database to choose only the images that matter for AI
reproduction.

Each AI-ready product should support:

```js
{
  main_image: "path/to/main.jpg",
  ai_reference_images: [
    "path/to/reference-1.jpg",
    "path/to/reference-2.jpg"
  ],
  ai_features: [
    "feature text"
  ],
  ai_prompt: "product-specific prompt"
}
```

Rules:

- Send the site/garden photo.
- Send `main_image`.
- Send up to 3 total product reference images, including `main_image`.
- Do not send the full gallery.
- Choose reference images by role, not by count.
- Do not assume front and 45-degree images are always the correct pair.
- Select images based on what makes that specific product identifiable.

## Reference Image Selection Rules

For each AI-ready product, choose up to 3 product reference images:

1. Overall form
   - Shows the full product silhouette.
   - Helps the AI understand size, proportion, and orientation.

2. Structural detail
   - Shows the part that makes the product identifiable.
   - Examples: mesh grid, door, faucet, frame, joint, surface texture.

3. Product-specific critical part
   - Depends on the product.
   - Pizza oven: door and wood storage.
   - Gabion: mesh and stone cage structure.
   - Water stand: faucet count/position and garden pan depth.

Avoid:

- Screenshots with large UI or sales text when a clean crop is possible.
- Sending every gallery image.
- Generic lifestyle photos that hide the product detail.
- Images that teach the wrong product shape.

Use:

- Cropped product images.
- Clean detail images.
- One real scene image only when it improves material/scale understanding.

## Prompting Rules

Each AI-ready product should include `ai_features` and `ai_prompt`.

`ai_features` should be short, factual product traits.

`ai_prompt` should say what must be preserved and what must not be changed into.

Example:

```text
普通の石積み塀ではなく、金網グリッドの中に自然石が詰まったガビオンとして再現する。
```

This is more useful than a generic product name.

## Technical Notes

Implemented behavior:

- `main_image` is included first.
- `ai_reference_images` are appended after `main_image`.
- Duplicate image paths are skipped.
- Total product reference images are limited to 3.
- `ai_features` and `ai_prompt` are included in the server-side prompt.
- If a reference image fails to load, the service logs the failure and continues.

This keeps the method practical for 100+ future products.

## Explicitly Not Included in Version 0.3

Version 0.3 does not include:

- placement AI
- placement rules
- construction case learning
- transparent PNG workflow
- 3D workflow
- segmentation
- pattern/tile replacement

These may be evaluated later, but they are outside this version.

## Decision

Version 0.3 product reference image method is adopted as the standard for
AI-ready products.

Future product additions should not rely on product name text alone.

Future AI-ready products should define:

- `main_image`
- `ai_reference_images`
- `ai_features`
- `ai_prompt`

Only products with curated references should be treated as AI-ready for Version
1.0.
